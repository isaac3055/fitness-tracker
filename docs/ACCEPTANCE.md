# V1.0 验收与边界

## 可自动化验证

- npm typecheck / test / build。
- Playwright 桌面与手机：配置缺失提示、演示只读、各模块可访问、退出清理。
- PostgreSQL：跨用户读、写、删除、匿名存取限制；同步幂等；删除样本；账号级联删除。
- iOS：工程编译、模拟器 XCTest；不依赖开发者签名或真实健康样本。

## 部署后验证（需要已配置服务）

1. A/B 两个测试账号注册、邮箱验证、登录、重置密码。
2. 各模块新增、编辑、删除；刷新与退出重登后持久化。
3. A 的请求无法通过伪造 user_id 读取或修改 B 的任何表数据。
4. 无登录 JWT 无法读取数据、调用同步或删除账号。
5. 检查 Vercel 预览和生产环境不共用敏感测试记录，Auth 重定向严格限制。
6. 导出记录与界面一致；删除账号后全部业务表无该用户记录。

## HealthKit 真机

1. 使用同一 Supabase 账号；首次同意云端同步，系统逐类授权。
2. 验证全授权、部分拒绝、全部拒绝、随后重新授权；均不把空值说成已授权。
3. 身体数据、训练、能量与健康 App 在同一时区下核对，容许当天尚未完成。
4. 重复同步无重复行；断网后游标不前移，恢复网络可重试。
5. 删除健康 App 的训练或体重样本，随后同步应删除云端同 UUID 行。
6. 退出 A 再登录 B，不复用 A 会话或游标，不把 A 健康数据写入 B，除非 B 明确授权这部手机的数据同步。
7. 静息+活动只计一次；权限缺失保持未知；手动与原生数据来源可区分。
8. 停止同步、撤销授权、锁屏、重启、后台交付延迟分别验证。V1 不承诺固定后台间隔。
9. 长历史超出批大小、过期会话刷新失败时，错误可见且不能丢失同步游标。
10. 公开仓库、构建产物与日志中没有真实健康导出、访问令牌或私钥。

## 发布前仍需完成的外部配置

- Supabase 实例与迁移、邮件服务、Auth 限流/验证码。
- Vercel 项目与环境变量、生产域名与重定向。
- Apple Developer 签名、HealthKit capability、真机验收、隐私政策和 App Store 审核资料。

以上依赖账户资源或真机的步骤不能由代码提交替代。
